## 4. Deadlines and operation ownership (R-P2; PROPOSED)
**Bounded runner, smallest form.** P owns every deadline itself through injected capabilities (no default timer, no default network): `deps.monotonic()` → finite non-decreasing ms; `deps.timers.arm(ms)` → `{ promise, cancel }` (native unpatched promise, own-data `cancel` function — B's handle rule). P never calls `setTimeout`. Justification for not importing B: B's guard couples outstanding-work ledgers and booking-step lifecycle; P needs only "race one native promise against one armed timer and keep observing the loser".
- **Ownership:** P creates one native `AbortController` per probe (captured constructor) and passes ONLY its `signal` to `send`. The optional caller `signal` (genuine) is observed through captured `EventTarget` methods; its abort aborts the current probe controller. P adds / removes only its own listeners.
- **Per probe, strictly in this order:** (1) caller signal aborted → `PROBE_CANCELLED`, STOP (nothing prepared); (2) remaining run budget `runEnd − monotonic()`; if < `max(1000, 0.1 × perProbeMs)` → `PROBE_BUDGET_EXHAUSTED`, STOP; (3) probe deadline = `min(perProbeMs, remaining)`; arm the timer FIRST (`arm` throws / bad handle / non-native promise → `PROBE_DEPENDENCY_FAILED`, STOP, no send); (4) recheck caller signal natively immediately before `send` (aborted → cancel timer, `PROBE_CANCELLED`, no send); (5) exactly one `send` call; a synchronous throw or a non-native / patched returned promise → `PROBE_TRANSPORT_FAILED`, STOP, operation marked `UNOBSERVABLE`; (6) race send settlement vs timer vs caller abort via the captured intrinsic `then` (unpatched-promise + intact-intrinsics rule of B / T). First cause wins and is recorded once: timer → abort the probe controller, `PROBE_TIMEOUT`; caller abort → `PROBE_CANCELLED`; settlement → checks of §1.1. (7) cancel the timer.
- **No next send after abort / timeout:** a stop cause set during preparation or while awaiting ends the loop; the next probe is `NOT_RUN` (`AFTER_STOP`). No retry, no second attempt of the same probe, no second probe after a stop.
- **Outstanding sends:** after a timeout / cancel the send may still be running (T waits for X; a cooperative X aborts on the signal, but a hostile or broken send may ignore it). P's `result` resolves anyway — bounded by `runMs` + one timer callback — because P never awaits the send past its deadline. The late settlement is observed (kind only: `LATE_FULFILLED` / `LATE_REJECTED`), never inspected, never used as evidence, never changes the frozen summary.
- **`finalize()`:** resolves after the outstanding send settles or after `tailMs` (its own armed timer): `{ tail: 'NONE' | 'LATE_FULFILLED' | 'LATE_REJECTED' | 'UNSETTLED' | 'UNOBSERVABLE' }`. A never-settling send yields `UNSETTLED` — P cannot stop arbitrary injected code (trust boundary stated, not a sandbox).
- **Priority:** the run budget dominates; a probe never gets more than the remaining run budget; the total `runMs` is the hard upper bound of `result` (given a functioning injected timer — a timer dependency that never fires is a broken trusted dependency, outside the guarantee).
