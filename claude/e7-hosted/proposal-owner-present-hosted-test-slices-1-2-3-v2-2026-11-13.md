## 6. Stop / uncertain outcomes and the exact reviewed admission for each (v2)
Governing source rules: the reservation runner header — "The first signal stops new steps / transports; persisted effects are reported, never hidden. **No retry / rerun.**"; test-cleanup lines 632–636 (`REQUEST_OUTCOME_UNKNOWN`: "the transaction may or may not have committed: read, report, STOP") and 718 (`WRITE_OUTCOME_UNKNOWN`: "the session stops; a resume needs its OWN pinned admission"). Slice 3 admits **only pristine `payment_captured`**; once `requestTestCleanup` may have committed, the state is `test_cleanup_pending` and **no existing hosted runner can resume it** — v1 proposed redos there and that is withdrawn.

Two classes, decided by whether a provider or DB EFFECT may have happened:

**Class P — provably PRE-effect refusals.** No transport was sent AND no state write occurred (the wrapper refused before the core, or the core refused before its first write/send). **Zero provider counts alone do NOT establish Class P**: the core may have written DB state (lease, version, op row) before refusing. Class P requires COMPLETE evidence, all of: (a) the result's write invocation counts are 0 and `actions` show no dispatch; (b) ROOT's pure SELECT after the run shows the intent `version` unchanged from the fresh proof, every operation row unchanged (state / attempts / dispatched_at), no `intent_work` lease, and the target and foreign fingerprints (§5a) unchanged except for nothing; (c) the run completed and reported (no interruption / cancelled job / missing result). **Missing, partial or contradictory evidence, or any interruption, defaults to Class E — no rerun.** Admission for a confirmed Class P: correct inputs / re-pin from main, run preflight again, then GO with the new planHash; nothing is being redone because nothing happened.
- Wrapper: `H*_USAGE / INPUT_INVALID / INPUT_INCOMPLETE / REF_NOT_MAIN / SOURCE_MISMATCH / RUNNER_MISMATCH / PLAN_HASH_MISMATCH / DEPENDENCY_MISMATCH / ENV_REFUSED / TESTS_FAILED / CHILD_FAILED / IMPORT_FAILED / CREDENTIALS_MISSING / SECRET_SCOPE_VIOLATION`.
- Core pre-step: `SCOPE_REFUSED`, `START_STATE_NOT_ELIGIBLE`, `SCHEMA_PREREQUISITE_MISSING`, `DB_IDENTITY_MISMATCH`, `LOCK_NOT_ACQUIRED`, `PROVIDER_PROOF_FAILED` **only when the result reports zero write invocations** (`createInvocations 0` / `captureInvocations 0` / `requestInvocations 0` and `cancelInvocations 0` / `refundInvocations 0`) and the result's `actions` show no dispatch. ROOT confirms with a pure SELECT that version and ops are unchanged before any new preflight.

**Class E — possibly-EFFECTED outcomes.** Anything after a transport was handed to a sender or a request transaction was begun: `*_OUTCOME_UNKNOWN`, `*_UNKNOWN_STATE`, `CREATE_OUTCOME_UNKNOWN`, `RESERVATION_UNKNOWN`, `CAPTURE_OUTCOME_UNKNOWN`, `CAPTURE_UNKNOWN_STATE`, `REQUEST_OUTCOME_UNKNOWN`, `WRITE_OUTCOME_UNKNOWN`, `CLEANUP_UNKNOWN_STATE`, `CLEANUP_ESCALATED`, `LINEAGE_MISMATCH` after the request, `POSTCHECK_MISMATCH`, `NOT_CONFIRMED`, and `LOCK_LOST / DB_ERROR / ABORTED / DEADLINE / STEP_BUDGET_EXHAUSTED / BUDGET_EXHAUSTED` **whenever any write invocation count is > 0 or any op is not `pending`**. Admission: **NONE hosted.** Read-only reconciliation (ROOT pure SELECT: intent state / version / ops / cases / ledger; provider read-only dashboards: Hostaway reservation by ref field 105433, Stripe PI / charges / refunds for the pinned ids) → then **human-owned completion only**, as a specifically reviewed owner action naming identity (intent id, R, pi_, ch_, re_) and the observed state. No hosted rerun, no new recovery code, no DB repair; reconciliation cases, journals and mismatches are preserved as evidence. A fresh version/proof does not make a Class-E state admissible to any existing runner.

The one accepted continuation that is NOT a retry: S1-A ending `STEP_BUDGET_EXHAUSTED` at `reservation_pending` with the create op `succeeded` (ref not echoed, F1). The create happened exactly once and is recorded; the `pending` admission (same bound intent id, pinned reservationId = the create's `result_ref`, fresh version) is the runner's own reviewed path. It performs **no provider writes** (reads of the reservation only) but it **does advance persisted DB state**: the worker re-reads, records the confirming read, transitions `reservation_pending → reservation_confirmed`, bumps the version, queues the pristine capture op and updates `intent_work`. Its precondition is exactly `createOps=["succeeded"]` + reservation id known + no lease; any other S1-A end state is Class P or Class E as above.
